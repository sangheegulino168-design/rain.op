# DNSTunnel · DNS 隧道 / 数据渗出检测

`rain.op` 每日安全小 Agent 系列的第 5 个：**流量监测**方向。

DNS 是很多攻击者眼中的"免费高速公路"：防火墙通常放行 DNS 查询，
于是隧道工具（iodine、dns2tcp 等）把数据塞进子域名里外传。
DNSTunnel 读取 DNS 查询日志，按攻击子域名聚合，用 6 组启发式特征打分，
揪出疑似隧道/数据渗出行为。

## 检测逻辑

| 特征 | 说明 |
|---|---|
| 超长子域名 | 标签 ≥40 字符，疑似编码载荷 |
| 高熵载荷 | 子域名平均熵 ≥3.8（base64 风格） |
| 异常记录类型 | 大量 TXT/NULL/CNAME 查询 |
| 海量唯一子域名 | ≥10 个不同 FQDN，疑似数据渗出 |
| 查询速率爆发 | 单客户端峰值 ≥30 次/分钟 |
| 集中来源 | 大量查询只来自极少数客户端 |

评分 0–100：≥70 高危，≥40 可疑，其余正常。

聚合粒度说明：4 段及以上的域名取后 3 段（如 `xxx.tunnel.evil.example.com`
→ `evil.example.com`），防止攻击子域名和主站正常流量混在一起互相污染。

## 怎么跑

```bash
# 演示模式：内置正常流量 + DNS 隧道 + 数据渗出 + 合法 SPF 查询
python dnstunnel.py --demo

# 分析本地日志文件（格式：时间戳 客户端IP 查询域名 查询类型）
python dnstunnel.py --file /var/log/dns.log

# 管道输入
cat dns.log | python dnstunnel.py

# 指定告警 JSON 输出路径
python dnstunnel.py --demo --json /tmp/alerts.json
```

## 诚实说明

这是启发式检测（"疑似"），不是确诊：DoH/DoT 加密的 DNS 看不到查询内容；
企业邮件网关等合法场景也会产生高熵 TXT。生产环境建议结合 DNS 防火墙
日志做二次确认。
